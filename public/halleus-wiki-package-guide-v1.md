# راهنمای ساخت بستهٔ استاندارد ویکی هالیوس

این فایل را مستقیماً به چت محتوانویسی بده و عنوان یا موضوع مقاله را هم مشخص کن. نسخه‌ای که از دکمهٔ «دانلود راهنمای به‌روز تولید محتوا» در پنل ادمین می‌گیری، فهرست زندهٔ دسته‌ها، مقاله‌های قابل لینک و همهٔ شناسه‌ها و slugهای رزروشده را در انتهای فایل دارد. برای هر سفارش تازه راهنما را دوباره دانلود کن؛ sitemap جایگزین این اطلاعات نیست.

## خروجی نهایی

- نام ZIP با `halleus-wiki-package-` شروع شود.
- ریشهٔ ZIP فقط `manifest.json` و پوشه‌های `articles` و در صورت نیاز `assets` را داشته باشد.
- تمام فایل‌ها UTF-8 باشند.
- هر مقاله یک `article_id` لاتین و پایدار داشته باشد که در نسخه‌های بعدی تغییر نکند.

```text
halleus-wiki-package-topic-v1.zip
├── manifest.json
├── articles/
│   └── stable-article-id.md
└── assets/
    └── illustration.webp
```

## نمونهٔ کامل manifest.json

```json
{
  "schema_version": 1,
  "package_id": "cluster-topic-001",
  "articles": [
    {
      "article_id": "stable-article-id",
      "version": 1,
      "file": "articles/stable-article-id.md",
      "title": "عنوان فارسی مقاله",
      "short_title": "عنوان کوتاه",
      "slug": "persian-topic-in-latin",
      "seo_title": "عنوان سئوی مقاله | ویکی هالیوس",
      "meta_description": "توضیح متای طبیعی و فارسی.",
      "category": "foundations",
      "tags": ["چارت تولد"],
      "summary": "خلاصهٔ کوتاه و انسانی مقاله.",
      "reading_minutes": 6,
      "publication_priority": 280,
      "content_cluster": "topic-cluster",
      "article_role": "pillar",
      "related_article_ids": ["another-stable-id"],
      "indexable": true,
      "sources": [
        { "label": "نام منبع معتبر", "href": "https://example.com/source" }
      ],
      "call_to_action": {
        "title": "چارت تولدت را بساز",
        "text": "برای خوانش شخصی، داده‌های تولدت را وارد کن.",
        "label": "ساخت چارت تولد",
        "href": "/chart"
      }
    }
  ],
  "assets": [
    {
      "path": "assets/illustration.webp",
      "alt": "توضیح دقیق فارسی تصویر"
    }
  ]
}
```

## معنی فیلدهای محتوایی و انتشار

- `article_role`: مقالهٔ اصلی یک خوشه `pillar` و مقالهٔ تکمیلی `support` است.
- `content_cluster`: شناسهٔ لاتین موضوع مشترک مقاله‌های مرتبط است.
- `publication_priority`: عدد صحیح بین ۰ تا ۳۰۰ است. عدد بزرگ‌تر زودتر در صف هم‌سطح قرار می‌گیرد؛ ترتیب وابستگی‌ها و تقدم pillar همچنان مقدم‌اند.
- اولویت را ترجیحاً مضرب ۱۰ انتخاب کن تا بین مقاله‌ها فضای جابه‌جایی باقی بماند.
- `250–300`: مقالهٔ اصلی `pillar` و پایهٔ ضروری خوشه؛ مقدار پیش‌فرض `280`.
- `180–240`: مقالهٔ پشتیبان ضروری، پیش‌نیاز مستقیم یا موضوعی که باید بلافاصله پس از pillar بیاید؛ مقدار پیش‌فرض `220`.
- `100–170`: مقالهٔ پشتیبان معمول و مهم؛ مقدار پیش‌فرض `140`.
- `0–90`: مقالهٔ فرعی، اختیاری یا مناسب backlog؛ مقدار پیش‌فرض `60`.
- مقدار خارج از بازهٔ ۰ تا ۳۰۰ پذیرفته نمی‌شود. فقط وقتی دلیل محتوایی واقعی وجود دارد از مقدار پیش‌فرض هر گروه فاصله بگیر.
- جدول «صف زندهٔ انتشار» در انتهای راهنما را بخوان و امتیاز مقالهٔ تازه را نسبت به مقاله‌های موجود انتخاب کن؛ جایگاه و تاریخ انتشار را در manifest ننویس.
- `related_article_ids`: همهٔ مقاله‌هایی که داخل متن به آن‌ها لینک داده شده‌اند.
- `indexable`: برای مقالهٔ عمومی و نهایی معمولاً `true` است؛ بدون تصمیم صریح آن را `false` نکن.
- `sources`: برای ادعاهای زمانی، نجومی، تاریخی یا علمی از منبع معتبر و ترجیحاً اولیه استفاده کن. منبع ساختگی نساز.
- `call_to_action`: اختیاری است؛ فقط CTA واقعی و مرتبط هالیوس مثل `/chart` یا `/wiki` استفاده شود.
- برای اصلاح همان مقاله، `article_id` ثابت، `slug` ترجیحاً ثابت و `version` بزرگ‌تر از نسخهٔ فعلی باشد.

## لینک‌سازی داخلی

- برای مقالهٔ تازه، اگر ارتباط واقعی وجود دارد ۲ تا ۴ لینک طبیعی به مقاله‌های منتشرشده اضافه کن.
- مقصدها را فقط از جدول «مقاله‌های منتشرشده و قابل لینک» در انتهای راهنمای زنده انتخاب کن.
- لینک داخل متن با `[[article:stable-id]]` نوشته شود و همان stable ID در `related_article_ids` هم قرار بگیرد.
- لینک را داخل جملهٔ مرتبط قرار بده؛ فهرست لینک مصنوعی، تکرار بی‌دلیل و لینک‌سازی اسپمی نساز.
- به draft، archived، deleted یا شناسه‌ای که در جدول قابل لینک نیست لینک نده.
- مقاله‌های داخل یک ZIP می‌توانند به یکدیگر لینک بدهند، به شرطی که همه در همان manifest تعریف شده باشند و وابستگی دوری ایجاد نکنند.

## نمونهٔ فایل مقاله

```md
مقدمهٔ مقاله با زبان طبیعی و فارسی.

## نکات کلیدی

- نکتهٔ نخست
- نکتهٔ دوم

## بخش اصلی

متن مقاله و یک لینک طبیعی به [[article:another-stable-id]] در همان جمله.

![توضیح تصویر](../assets/illustration.webp)
```

## ساختار مجاز Markdown

- پاراگراف عادی
- تیتر بخش فقط با `##`
- فهرست نقطه‌ای فقط با `- `
- تصویر اعلام‌شده در manifest
- لینک داخلی پایدار با `[[article:stable-id]]`

از H1، تیتر H3 تا H6، نقل‌قول با `>`، فهرست شماره‌دار، code block، HTML خام، لینک Markdown معمولی و نشانه‌های bold/italic مثل `**متن**` استفاده نکن. یادآوری یا توضیح تکمیلی را به‌صورت پاراگراف عادی بنویس.

## قواعد شناسه، دسته و فایل

- `article_id` فقط از حروف کوچک لاتین، عدد، نقطه، خط تیره یا زیرخط ساخته شود.
- `slug` فقط حروف کوچک لاتین، عدد و خط تیره داشته باشد.
- برای مقالهٔ تازه هیچ `article_id` یا `slug` رزروشده‌ای را تکرار نکن.
- دسته فقط از فهرست «دسته‌های مجاز فعلی» انتخاب شود.
- تصویر فقط PNG، JPEG یا WebP باشد و حتماً در `assets` معرفی شود؛ alt دقیق و فارسی لازم است.
- HTML خام، فایل اجرایی، مسیر مطلق، مسیر ناامن، فایل اعلام‌نشده و URL با پروتکل ناامن پذیرفته نمی‌شود.
- مقالهٔ ناقص یا ناسالم قرنطینه می‌شود و مقاله‌های سالم همان بسته از بین نمی‌روند.
- ورود بسته مقالهٔ منتشرشده را بی‌صدا بازنویسی نمی‌کند؛ ابتدا draft یا revision ساخته می‌شود.

## کیفیت متن و SEO

- لحن انسانی، روان و فارسی هالیوس باشد؛ متن خشک دانشنامه‌ای یا ماشینی نباشد.
- در نام برند داخل متن «هالیوس» بنویس، مگر در URL یا شناسهٔ فنی.
- عنوان، `seo_title`، توضیح متا، summary و tags طبیعی و هماهنگ با intent مقاله باشند.
- ادعاهای قطعی، اغراق‌آمیز یا بدون منبع نساز و متن تکراری برای پرکردن حجم اضافه نکن.
- مقاله باید برای مخاطب فارسی‌زبان مثال و توضیح قابل‌فهم داشته باشد.

## دستور پیشنهادی برای چت محتوانویسی

«موضوع خواسته‌شده را با لحن انسانی و فارسی هالیوس بنویس و یک ZIP کاملاً مطابق همین راهنمای به‌روز تحویل بده. فقط از دسته‌های مجاز فعلی استفاده کن و برای مقالهٔ تازه هیچ article_id یا slug رزروشده‌ای را تکرار نکن. در صورت ارتباط واقعی، ۲ تا ۴ لینک طبیعی به مقاله‌های جدول قابل لینک اضافه کن؛ لینک‌ها را هم داخل متن با الگوی stable و هم در related_article_ids ثبت کن. جدول صف زنده را بخوان و برای هر مقاله `publication_priority` را فقط در بازهٔ ۰ تا ۳۰۰ و طبق باندهای تعریف‌شده انتخاب کن؛ جایگاه یا تاریخ انتشار را داخل manifest نساز. نقش pillar/support، content_cluster، وابستگی‌ها، نسخه، SEO، منابع معتبر، CTA مرتبط، تصاویر و manifest را دقیق رعایت کن. متن مقاله فقط شامل پاراگراف، H2، فهرست نقطه‌ای، تصویر اعلام‌شده و لینک پایدار باشد؛ HTML، blockquote، bold/italic و فایل اعلام‌نشده نساز.»

بازبینی ۲۱ نوامبر ۲۰۲۶ · نقطهٔ شروع کد `100a6e1` · **وضعیت فعلی: آمادهٔ انتشار نیست.** اولین کار باز، تطبیق نسخه و تنظیمات گزارش‌های ۴۸ و ۶۴ با یک اجرای کنترل‌شده روی همان خانوادهٔ مرورگر است. برای شروع به چت قبلی، فایل‌های موقت Work یا VPS نیاز نیست.

## قاعدهٔ کار و ثبت پیشرفت

هر ردیف زیر یک واحد بررسی است. خروجی در پوشهٔ محلی شواهد خارج از worktree نگه‌داری شود. در پایان هر نشست، نسخهٔ کاری و دفتر شواهد را در مسیر پایدار مجری نگه دار. خلاصهٔ تحویل شامل اولین شناسهٔ باز، آخرین کاندیدای پذیرفته‌شده، تعداد مسیرهای قبول از کل، مسیرهای زیر هدف و محل شواهد باشد. هنگام انتقال محیط، اثرانگشت‌ها را تطبیق بده. قالب یک سطر دفتر کار:

```text
ID | URL/سناریو | SHA + hash diff شامل فایل‌های تازه | build ID | fixture/config/browser | شاخص اصلی قبل→بعد | شاهد (JSON/trace/عکس/تست) | وضعیت | اولین قدم باز
```

برای ورودیِ یکسان، نتیجهٔ سبز پیشین را با `RESUMED_PASS` نگه دار. برای runner یا ورودی تازه، تنها قسمت وابسته تکرار شود. `SAFETY_FATAL` برای مرجع اشتباه، درخت نامرتبط، اتصال تولید یا اقدام خارج از دامنه توقف فوری است. شکست کاندیدا `CANDIDATE_FAILURE`، نقص اثبات‌شدهٔ مرجع `UNRELATED_BASELINE_FAILURE`، مانع محیط `EXTERNAL_BLOCK` و نتیجهٔ وابسته `BLOCKED_BY_DEPENDENCY` است. در R1 تمام آزمون‌های مستقل و امن را کامل کن؛ در R2 همان کاندیدا را ترمیم کن. فقط نتیجهٔ تجمیعی قابل انتشار است. trace، شناسهٔ نشست، ورودی تولد، توکن، فایل env و گزارش شخصی در مخزن عمومی قرار نگیرند.

**پروفایل مشترک آزمایش.** Lighthouse دقیقاً `13.5.0`، حالت navigation/performance، Chrome ثابت و پروفایل تازه بدون افزونه برای هر اجرای سرد. مقدارهای زیر بخش settings پیکربندی Lighthouse هستند. بعد از اجرا آن‌ها را در `configSettings` فایل JSON کنترل کن. ابزار را خارج از پروژه نصب کن. پروفایل دسکتاپ مستقل است. Chrome و نسخهٔ ابزار دو طرف باید برابر باشند.

```js
// mobile.cjs — فایل محلی کنار خروجی‌های آزمون
module.exports = {
  extends: 'lighthouse:default',
  settings: {
    onlyCategories: ['performance'], formFactor: 'mobile',
    screenEmulation: { mobile: true, width: 412, height: 823, deviceScaleFactor: 1.75, disabled: false },
    throttlingMethod: 'simulate',
    throttling: { rttMs: 150, throughputKbps: 1638.4, requestLatencyMs: 562.5,
      downloadThroughputKbps: 1474.56, uploadThroughputKbps: 675, cpuSlowdownMultiplier: 4 }
  }
};
```

نمونهٔ یک اجرا در پوشهٔ آزمایش ویندوز پس از بالا آمدن build صحیح و تنظیم مقصد تست آمار؛ برای هر اجرا نام یکتا بده. در قدم 08 برای ثبت trace و گزارش شبکه، گزینهٔ `--save-assets` را به اجرای تشخیصی اضافه کن. آزمون امتیاز را جدا از ضبط Playwright یا DevTools و هر build هم‌زمان اجرا کن.

```powershell
npx --yes --package=lighthouse@13.5.0 lighthouse http://127.0.0.1:3218/chart --config-path=./mobile.cjs --chrome-flags="--headless=new" --output=json --output-path=./S-chart-r01.json
```

در صورت دسترسی به چند Chrome، مسیر فایل اجراییِ نسخهٔ ثبت‌شده را با `CHROME_PATH` ثابت کن. desktop UA یا حالت devtools دسکتاپ با عرض کوچک جای emulation موبایل را نمی‌گیرد.

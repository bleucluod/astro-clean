# رودمپ فعال بازطراحی «نمای کلی» ادمین هالیوس

## هدف و دامنهٔ تأییدشده

نمای کلی `/admini?tab=overview` باید از شش شمارندهٔ ساده به مرکز پایش کسب‌وکار و عملیات روزانه تبدیل شود. این رودمپ فقط شامل همین صفحه، خوانش تجمیعیِ خصوصیِ داده‌ها، آزمون‌های مرتبط و در صورت تصویب نهایی انتشار رسمی آن است. هیچ تغییر DB schema، Nginx، auth policy، SEO عمومی یا سیستم خارجی خارج از همین خواسته مجاز نیست.

## مبنای واقعی

- آخرین GitHub main هنگام بررسی: `6fdfaa60aaa826b9815c03be9275da5c2f7627f1`. وضعیت اعلام‌شدهٔ VPS پیش از شروع: همان Release با `PRODUCTION_SHOP_ORDER_UX=LIVE_VERIFIED`.
- منبع شش شمارندهٔ موجود: `/api/admin/overview` و `getAdminOverview()` در `lib/admin/admin-service.ts`.
- داده‌های کاربران/گزارش‌ها در `public.halleus_users` و `public.halleus_reports`، سفارش‌ها در `halleus_private.shop_orders`، ویکی در `public.wiki_articles` و `halleus_private.wiki_publish_jobs`، تلگرام در `halleus_private.telegram_content_queue`. منبع جزئیات جدول‌ها مهاجرت‌های موجود پروژه است، نه حدس توپولوژی Supabase.
- نمودار از دادهٔ تجمیعی روز تهران تشکیل می‌شود، نه دادهٔ شخصی و نه GA4 یا Search Console زنده. Search Console فعلاً ورودی CSV دارد؛ تاریخ تازه‌سازی آن نباید نامشخص جلوه کند.

## برش پیاده‌سازی یکپارچه

1. API خصوصی تجمیع روزانه برای ۷/۳۰/۹۰/۳۶۵ روز با ۲ برابر بازهٔ قابل قیاس؛ دسترسی `dashboard.read` الزامی، خواندن فروش فقط برای مالک دارای `shop_orders.read` و خواندن محتوای تخصصی فقط با capability مربوطه. بدون نام، موبایل، تاریخ تولد، نشانی یا متن گزارش در payload.
2. کارت‌های شاخص: گزارش‌های ساخته‌شده، کاربران جدید، سفارش ثبت‌شده و مبلغ پرداخت تأییدشده (اگر مجاز باشد)، با مقایسهٔ بازهٔ قبلی؛ نمودار روزانه/هفتگی/ماهانه، دسته‌های رشد/گزارش/فروش/ویکی/تلگرام/ترکیبی، حداکثر دو خط انتخابی، دو محور واضح برای مقیاس‌های بسیار متفاوت، حالت تعداد/تومان، tooltip و انتخاب نقطه با ورودی قابل‌دسترسی.
3. نشانگر واقعی افتتاح P01 در ۸ نوامبر ۲۰۲۶، بدون ساخت رویدادهای کمپین حدسی. خلاصهٔ عملیاتی فقط برای موارد نیازمند اقدام و خلاصهٔ محتوای واقعی؛ لینک مستقیم به بخش‌های تخصصی. داشبورد واکنش‌گرا و هم‌رنگ رابط سرد هالیوس.
4. گاردهای جداگانهٔ سناریوهای نقش مالک/غیرمالک، no-store، عدم افشای داده‌های شخصی، نمونه‌های مصنوعی SQL و کنترل ساختار TSX/CSS؛ سپس TypeScript/ESLint، بررسی diff و Build واقعی به‌علت تغییر مسیر runtime.

## قرارداد شاخص‌ها

- «فروش تأییدشده»: جمع ارزش سفارش دارای `payment_verified_at` و غیرفعال‌شده نبودن وضعیت لغو؛ این شاخص صورت‌حساب بانکی یا خالص مرجوعی نیست. زمان رخداد فروش، زمان تأیید پرداخت است؛ جمع مبلغ سفارش بر اساس زمان ایجاد سفارش جداگانه می‌ماند.
- «گزارش‌های ساخته‌شده»: گزارش‌های ذخیره‌شدهٔ حذف‌نشده؛ آمار مهمان/حساب‌دار از `source` و نوع چارت از متادیتای واقعی گزارش گرفته می‌شود.
- «مقالهٔ منتشرشده»: مقاله‌هایی که اکنون منتشر و حذف‌نشده‌اند، بر مبنای `published_at`. «پیش‌نویس» فقط مقالاتی است که اکنون draft هستند، بر مبنای تاریخ ایجاد.
- «پیام آماده/پیش‌نویس» تلگرام، وضعیت کنونی صف است؛ پیام منتشرشده بر مبنای `published_at` و شکست بر مبنای آخرین تلاش. «ناموفق نیازمند توجه» طبق مرز تأخیر واقعی سرویس تلگرام شمرده می‌شود.
- «کاربر فعال»، «نرخ تبدیل فروش»، «درآمد خالص» و «کلیک‌های زندهٔ GSC» بدون داده/تعریف معتبر به‌عنوان عدد قطعی نمایش داده نمی‌شوند.

## وضعیت و نقطهٔ ادامه

### R1 کامل و ادامهٔ R2 — ۲۰۲۶-۱۱-۰۸

**تکمیل همان Failure Class پیش از اجرای R2:** گارد `admin_ux` در R1 با اولین Assertion متوقف شده بود. با بررسی ترتیبیِ همهٔ Assertionهای بعدی در سورس واقعی، چند انتظار قدیمی دیگر نیز در همان گارد مشخص شد: متن سلامت تلگرام، نام دکمهٔ ساخت Smart Pack، صفحه‌بندی ۲۵تایی گزارش‌ها در حالی‌که نمای روزانه ۱۰ و عملیات ۲۵ مورد است، کارت‌های کنونی گزارش‌ها، و عنوان `Advanced` ابزارهای ویکی. همهٔ این موارد صرفاً تغییر ساختار/نام در کامپوننت‌های فعلی‌اند؛ تست متناسب با مسیرهای واقعی فایل‌پیکر، بستهٔ تلگرام، صفحه‌بندی/کارت گزارش و disclosure ویکی اصلاح و بر پایهٔ سورس GitHub اعتبارسنجی شد. هیچ کامپوننت، حریم خصوصی یا قرارداد داده‌ای تغییر نکرد و **PASS اجرایی R2 هنوز منتظر خروجی VPS است**. برای این اصلاح گارد جامع از تگ انتشار مستقل `v2026.11.08-admin-overview-r4` استفاده می‌شود.

- **GitHub base/Commit آزموده‌شده:** `961a653c9479cd66a6ad7c4fb96bcab5f9c5781e`. در خروجی واقعی VPS، سورس `main` به این Commit رسید و گیت‌های ایمنی `SAFETY_PREFLIGHT=PASS` شدند. کاندیدای worktree جداگانه ایجاد شد ولی Deploy شروع نشد.
- **R1 پاس‌شده:** `focused_dashboard`، `admin_ia`، `typescript`، `eslint`، `diff_check` و `live_database_readonly`، با شواهد `/tmp/halleus-admin-overview-U10DNsyU`.
- **R1 شکست‌های مستقل:** `admin_ux` در Assertion نام قدیمی فایل‌پیکر تلگرام؛ `admin_routes` در تشخیص شرط `pathname === "/admin"` و `pathname.startsWith("/admin/")` در هدر به‌عنوان لینک ناوبری؛ `secure_admin` در متن قدیمی رضایت انتشار پرمیوم. تطبیق سورس واقعی نشان داد فایل‌پیکر کنونی `styles.telegramFileField` به همراه `type="file"` و JSON accept دارد؛ شرط‌های هدر صرفاً برای جداسازی chrome خصوصی‌اند؛ فرم پرمیوم پیش‌فرض `not_requested` و انتخاب صریح `public_with_consent` دارد.
- **R2:** فقط سه گارد فوق مطابق قرارداد عملی فعلی اصلاح شوند. برش به صفحهٔ دیگر، متن درخواست پرمیوم، دسترسی‌های ادمین، داده و قوانین Supabase، تلگرام یا محصول فروشگاه دست نمی‌زند. R2 مراحل PASS با ورودی بدون تغییر را فقط با وجود شواهد لاگ `RESUMED_PASS` می‌کند؛ سه گارد شکست‌خورده، ESLint گاردها، `git diff --check` و خوانش read-only دیتابیس را دوباره اجرا می‌کند. شکست‌های معمول جمع‌آوری شوند و تا پیش از پاس‌بودن همهٔ گیت‌ها Build و Deploy رسمی انجام نشود.
- **انتشار:** فقط با موتور `ops/vps/halleus-release.sh`، تگ جدید و بررسی current/previous، service و live smoke. `ROADMAP_COMPLETE` فقط بعد از تأیید واقعی این مرحله روی سایت زنده مجاز است.

### اصلاح گیت ایمنی R2 — ۲۰۲۶-۱۱-۰۸

- **نتیجهٔ تلاش قبلی:** دستور VPS مربوط به Commit `7bdcd9bddbfeffb69f95cae0f557c6d0da663d31` پیش از Fetch، ساخت کاندیدا یا Deploy با `SAFETY_FATAL: Unexpected HEAD` متوقف شد؛ اجرای هیچ‌یک از آزمون‌ها آغاز نشده است. `HEAD` واقعی VPS در آن خروجی چاپ نشده، بنابراین وضعیت دقیق آن را حدس نمی‌زنیم.
- **علت قطعی:** گیتِ پیش از Fetch در بلوک بیرونی و اسکریپت GitHub فقط `f160ced6f5bd6a947067b27a1a80f4a8fb4a14f3` یا `7bdcd9bddbfeffb69f95cae0f557c6d0da663d31` را می‌پذیرفت، در حالی که GitHub از نسخهٔ فعال تأییدشدهٔ فروشگاه `6fdfaa60aaa826b9815c03be9275da5c2f7627f1` دو Commit جلوتر بود و سورس VPS ممکن است هنوز روی آن نسخه باشد.
- **R2 امن:** گیت فقط چهار SHA شناخته‌شده را می‌پذیرد: نسخهٔ فعال قبلی، Commit داشبورد اولیه، Commit گیت R1 و Commit گیت R2. پس از Fetch، اجداد بودن `HEAD` نسبت به Commit هدف و تطبیق والد R2، Origin، Branch، تمیزی Worktree و مسیر فایل‌های مجاز مجدداً بررسی می‌شوند. `git reset` یا تغییرات مخرب نداریم.
- **نقطهٔ ادامه:** ابتدا R1 کامل آزمون‌های مستقل روی کاندیدای جدید اجرا شود؛ در صورت PASS، انتشار اتمیک با `ops/vps/halleus-release.sh`، Smoke و در صورت لزوم Rollback رسمی. فقط خروجی VPS می‌تواند `ADMIN_OVERVIEW_PRODUCTION=LIVE_VERIFIED` را ثابت کند.

### گیت فنی انتشار — ۲۰۲۶-۱۱-۰۸

- **HEAD پایه:** `f160ced6f5bd6a947067b27a1a80f4a8fb4a14f3`؛ در نسخهٔ فعال VPS طبق آخرین لاگ مالک `6fdfaa60aaa826b9815c03be9275da5c2f7627f1` با فروش P01 فعال است.
- **اصلاح گارد تاریخی:** `check-admin-ux-consolidation.mjs` هنوز `styles.quickActions` در کامپوننت قدیمی می‌خواست؛ برای داشبورد جدید، mount کامپوننت و اتصال اقدام‌ها و خلاصهٔ محتوا را بررسی می‌کند. سایر تست‌های تخصصی ادمین حفظ می‌شوند.
- **R1 کامل، پیش از هر فعال‌سازی:** درخت کاندیدای ایزوله از Commit معتبر، آزمون اختصاصی داشبورد، admin UX، admin routes، admin IA، secure admin، TypeScript، ESLint و diff check. هم‌زمان کوئری‌های واقعی داده‌های تجمیعی با قرارداد role مالک/غیرمالک فقط داخل تراکنش PostgreSQL `read only` و با تنظیمات DB خود سرویس در حال اجرای VPS بررسی می‌شوند. هیچ credential در لاگ چاپ نشود.
- **نتیجهٔ آزمون‌ها:** تا اجرای VPS **NOT_RUN**، نه PASS؛ هر شکست عادی جمع‌آوری و با نام root stage و فایل لاگ جدا گزارش شود و هیچ Release انجام نشود. فقط SAFETY_FATAL اجرای مراحل را فوراً متوقف می‌کند.
- **انتشار و بازگشت:** پس از پاس‌شدن همهٔ گیت‌های پیش‌انتشار، تگ دقیق در GitHub ثبت و فقط Release رسمی با skip ویکی انجام شود. بعد از آن وضعیت current/previous، سرویس، صفحهٔ ادمین و عدم دسترسی عمومی API بررسی و در صورت شکست smoke از rollback رسمی استفاده شود. DB، Nginx، ENV و فایل‌های قدیمی فروشگاه خارج از دامنه‌اند.
- **نتیجهٔ زنده:** تنها با خروجی واقعی VPS و نشانگر `ADMIN_OVERVIEW_PRODUCTION=LIVE_VERIFIED` قابل تأیید است. اعتبار و صحت همهٔ اعداد در حضور حساب مدیر پس از انتشار باید جداگانه بازبینی شود.

- **مجوز فعلی:** مالک در گفتگو صریحاً خواست همین برش روی GitHub `main` ثبت شود و خودش Pull کند؛ تأیید Commit/Push وجود دارد. Runner ویندوزی تحویل داده نمی‌شود و VPS بدون مجوز جداگانه تغییر نخواهد کرد.
- **گیت بعدی:** گارد `scripts/check-admin-overview-dashboard.mjs`، `tsc --noEmit`، ESLint فایل‌های تغییرکرده، `git diff --check` و Build به‌دلیل تغییر API runtime باید پیش از هر انتشار VPS اجرا شوند. بررسی ساختاری GitHub جایگزین اجرای این آزمون‌ها نیست.
- **مجوز انتشار:** مالک در همین گفتگو صریحاً خواست تمام اقدامات در GitHub انجام شوند و فقط یک دستور VPS در پایان دریافت کند. تأیید اعمال و انتشار این رودمپ موجود است. مسیر انتشار باید فقط `ops/vps/halleus-admin-overview-release.sh` به‌عنوان گارد preflight و سپس `ops/vps/halleus-release.sh` به‌عنوان موتور اتمیک باشد؛ خود دستور VPS تنها پس از Commit گاردهای جدید ارائه شود.
